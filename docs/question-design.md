# 진단 문항 설계 가이드

## 1. 목표

사용자가 약 10분 안에 응답할 수 있으면서도, 12축 사용자 벡터를 만들 수 있는 문항을 설계합니다.

## 2. 권장 문항 구성

| 모듈 | 내용 | 수 | 필수 |
| --- | --- | ---: | --- |
| 안내 | 서비스 한계와 데이터 사용 안내 | 1 | 예 |
| 선택형 자기이해 | MBTI·애니어그램·간단 Big Five | 0~5 | 아니오 |
| RIASEC 코어 | 6축 × 2문항, 리커트 5점 | 12 | 예 |
| 핵심역량 코어 | 6축 × 2문항, 리커트 5점 | 12 | 예 |
| 공통 SJT | 문제 상황과 첫 행동 선택 | 4 | 예 |
| 분기 SJT | 공통 선택에 연결된 후속 문항 | 2~4 | 예 |
| 현실 조건 | 학력·전공·경력·지역·연봉·환경 | 6~9 | 권장 |

## 3. 문항 작성 규칙

- 한 문항에는 한 행동 또는 한 선호만 묻습니다.
- 어려운 직무 용어 대신 일상적인 상황을 사용합니다.
- “좋아 보이는 답”이 하나만 남지 않도록 선택지마다 장단점을 둡니다.
- 리커트 문항은 `1 전혀 아니다`부터 `5 매우 그렇다`까지 같은 방향으로 둡니다.
- 역문항을 쓰면 `reverse: true`로 표시하고 점수 계산에서 뒤집습니다.
- SJT는 “어떤 직군이 좋아요?”라고 직접 묻지 않습니다.

## 4. SJT 분기 방식

1. 공통 SJT 4개에서 사용자의 문제 선택과 첫 행동을 받습니다.
2. 각 선택지에는 주 신호 1개와 보조 신호 1개를 연결합니다.
3. 가장 높게 누적된 관심 클러스터 2개에 연결된 후속 SJT 2~4개만 보여 줍니다.
4. SJT 점수는 연결된 12축에만 보강 신호로 반영합니다.

예시:

```text
프로젝트 일정이 밀리고 있습니다. 첫 행동은 무엇인가요?

A. 원인과 일정 데이터를 다시 확인한다.        → LO +2, I +1
B. 팀원과 역할·우선순위를 다시 정한다.        → CO +2, SE +1
C. 이해관계자에게 상황과 선택지를 공유한다.    → CM +2, E +1
D. 범위를 줄이고 오늘 끝낼 일을 정한다.        → SE +2, PE +1
```

## 5. `questions.json` 예시

```json
{
  "question_id": "RIASEC_I_01",
  "version": "0.1",
  "module": "core_likert",
  "axis": "I",
  "prompt": "새로운 자료와 원리를 파고들어 원인을 찾는 활동을 좋아한다.",
  "scale": {"min": 1, "max": 5, "labels": ["전혀 아니다", "매우 그렇다"]},
  "reverse": false,
  "required": true
}
```

```json
{
  "question_id": "SJT_COMMON_01",
  "module": "sjt",
  "prompt": "프로젝트 일정이 밀리고 있습니다. 첫 행동은 무엇인가요?",
  "options": [
    {"id": "A", "label": "원인과 일정 데이터를 다시 확인한다.", "signals": {"LO": 2, "I": 1}},
    {"id": "B", "label": "팀원과 역할과 우선순위를 다시 정한다.", "signals": {"CO": 2, "SE": 1}}
  ],
  "required": true
}
```

## 6. 출시 전 검토

- [ ] 축마다 리커트 문항이 정확히 2개씩 있는가?
- [ ] 문항 문장이 중학생도 이해할 수 있는가?
- [ ] SJT 모든 선택지에 점수 맵이 있는가?
- [ ] 특정 성별·나이·직업을 좋거나 나쁘게 보이게 하지 않는가?
- [ ] 대표 사용자 3명이 7~12분 안에 끝내는가?
