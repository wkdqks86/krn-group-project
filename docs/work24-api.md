# 고용24·공공데이터 API 활용 계획

## 1. 목적

추천 엔진이 정한 직군 TOP 5에 대해 사용자가 실제로 탐색할 수 있는 직업·채용 정보를 제공합니다. API는 추천 점수를 계산하지 않습니다.

## 2. 우선 데이터

| 데이터 | 화면에서의 사용 | MVP 처리 |
| --- | --- | --- |
| 워크넷 직업정보 API | 직군별 연관 직업 검색·직업 상세 | 핵심 직업을 직군에 미리 매핑하고, 가능하면 최신 상세를 조회 |
| 워크넷 채용정보 API | 희망 지역·경력 등에 맞는 채용 예시 | 직군 상세에 최대 3개 예시와 원문 링크 표시 |
| 직업분류·직업별 임금 정보 | 직업 카드의 보조 정보 | 라이선스·갱신일 확인 후 검수된 스냅샷 사용 |

공식 정보:

- [한국고용정보원_워크넷_직업정보](https://www.data.go.kr/data/3071087/openapi.do)
- [한국고용정보원_워크넷 채용정보 채용목록 및 상세정보](https://www.data.go.kr/data/3038225/openapi.do)
- [워크넷 OpenAPI 이용가이드](https://lod.work.go.kr/openAPI_guide.do)

## 3. API 키와 보안

- API 사용 전 데이터셋별 활용 신청, 인증키, 이용허락 범위를 확인합니다.
- 키는 `.streamlit/secrets.toml` 또는 환경변수에 넣습니다.
- `.streamlit/secrets.toml`, `.env`, 실제 키는 GitHub에 올리지 않습니다.
- 앱 로그에 API 키와 사용자의 민감한 입력값을 남기지 않습니다.

`.streamlit/secrets.toml` 예시:

```toml
WORK24_API_KEY = "여기에만_실제_키를_입력"
```

## 4. API 실패 대비

발표 중 API가 실패해도 결과 화면이 멈추지 않게 아래 순서로 동작합니다.

```text
1. 캐시에 있는 최근 응답 확인
2. 없으면 data/occupations.json의 검수된 스냅샷 사용
3. 그래도 없으면 직군 설명과 고용24 원문 링크만 표시
```

API 실패는 추천 점수와 TOP 5 결과에 영향을 주면 안 됩니다.

## 5. 출처 표기

직업·채용 카드 하단에 아래처럼 표시합니다.

```text
출처: 한국고용정보원 Work24 | 조회일: YYYY-MM-DD
```

스냅샷이면 아래처럼 표시합니다.

```text
출처: 팀 검수 스냅샷 | 원본: Work24 | 갱신일: YYYY-MM-DD
```

## 6. 개발 체크리스트

- [ ] API 키 발급과 이용허락 범위 확인
- [ ] 요청 timeout과 오류 처리
- [ ] 1분 이상 캐시 또는 결과별 1회 호출
- [ ] 직군별 연관 직업 3~5개 사전 매핑
- [ ] `occupations.json` fallback 데이터 준비
- [ ] 화면에 출처와 조회일 표시
- [ ] API 키가 Git 기록에 없는지 확인
