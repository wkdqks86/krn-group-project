## 2026-08-17 · 저장소 기초 세팅

### 확정 (PRD)

- 타깃: 20~30대 취업준비생
- 결과: 대분류 직군 8개 중 TOP 5, 상대 적합도
- 점수: RIASEC 6 + 핵심역량 6, 리커트 70% + SJT 30%
- MBTI / 애니어그램 / Big Five / 현실 조건은 추천 점수에 넣지 않음
- LLM은 설명만, 점수·순위 재계산 금지
- 데이터: JSON seed + 스냅샷 fallback. API 키는 secrets
- 기술: Streamlit + Python

### 이번 세팅에서 한 일

- GitHub Desktop으로 클론한 빈 저장소에 PRD 권장 폴더 구조를 만듦
- 문항·8개 직군 프로파일·직업 스냅샷 v0.1 초안을 JSON으로 넣음
- 핵심역량은 축당 1문항이 기본이고, 가중치가 큰 문제해결·논리만 2문항으로 보강(RIASEC 12 + 역량 8 + SJT 4 + 후속 4 = 28문항)
- 적합도 공식과 SJT 분기를 코드로 옮기고 회귀 테스트를 추가함
- Streamlit 화면 A~G 흐름이 로컬에서 끝까지 동작하도록 연결함

### 아직 회의에서 확정해야 할 것

## 2026-08-18 · P2 결과·화면 문구 톤앤보이스 정합 (v0.1)

### 결정

- 사용자 대면 문구의 단일 출처로 `data/copy.json`(P2 소유)을 신설. 화면 microcopy·결과 근거/주의 템플릿·밴드 라벨·금지어 목록을 한곳에서 관리.
- `services/explainer.py`는 점수를 재계산하지 않고 `copy.json`의 템플릿에 `component_scores`/`cautions`의 축 라벨만 끼워 문장을 만든다(함수 시그니처 불변, LLM 분리 유지).
- `app.py`는 랜딩 첫 줄·시작 버튼·진행 격려·계산 대기 스피너·결과 상단/마무리 문구를 `copy.json`에서 읽도록 연결(로직 변경 없음, 문구만 교체).
- 결과 밴드는 엔진의 순위 기반 라벨(가장 높은/높은/함께 탐색)을 유지하되, 화면에는 완화된 표현으로 매핑("지금 가장 먼저 살펴볼 만해요" 등).

### 이유

- 기존 결과 문구가 "○○ 응답(72)이 프로파일(85)과 가깝습니다"처럼 기계적이었고, 시트의 톤앤보이스 규칙(응답 인용 후 응원, 결핍어·단정어·예측어 금지, 감탄사·이모지 금지)이 화면에 반영되지 않았음.
- 문구를 코드에서 분리(copy.json)해, P2가 엔진·화면 코드를 건드리지 않고 카피만 교체·리뷰할 수 있게 함.

### 검증

- `pytest -q` 6/6 통과(엔진·분기 회귀 영향 없음).
- 데이터 성향 응답자 시뮬레이션에서 TOP5 근거/주의 문구가 정상 출력되고, 결핍·단정·예측 금지어 0건(랜딩의 승인 문구 "정답을 찾아 주지는 못해요"는 의도된 예외).

### 남은 P2 항목(회의 확정)

- 직군별 12축 요구값·가중치 워크숍(D-13): 현재 `job_profiles.json` 값은 v0.1 가설. 회귀 테스트(J03 최상위 기대)와 얽혀 있어 조정 시 `tests/test_scoring.py`도 함께 검토.
- 문항 원문 다듬기(D-18).
- 밴드 표현 문구 최종 컨펌(카피 리뷰).

### 버전

- `copy_version`: 0.1.0

## 2026-08-18 · P2 연관 직업 콘텐츠 보강 (v0.1.1)

### 결정

- `data/occupations.json`의 8개 직군 × 3개(총 24개) 연관 직업을 유지하되, 내용을 두 겹으로 보강.
  - `summary`: 한 줄 요약을 조금 더 구체적으로(무엇을, 어떻게 하는지 한 절 추가).
  - `fit_hint`(신규 필드): "~하면 잘 맞을 수 있어요" 톤으로, 해당 직업의 실제 업무 특성과 이어지는 성향 힌트 한 줄. 결핍어·단정어·예측어 금지 검증 통과.
- `app.py` detail 화면에 `fit_hint` 렌더링 한 줄 추가(있을 때만 표시, 로직 변경 없음).

### 이유

- 사용자가 detail 화면에서 "콘텐츠가 너무 단순하다"고 지적. 원인은 스키마 자체가 요약 1줄 + 업무 키워드 3개뿐이었기 때문(전 직군 공통, 버그 아님).
- 직업 개수(3개)를 늘리는 대신, 있는 3개의 내용 밀도를 높이는 쪽으로 범위를 좁힘(팀 확인).

### 확인 필요(P5에게 별도 전달)

- `services/work24.py`가 `WORK24_API_KEY`를 읽는데 `.streamlit/secrets.toml.example`은 `WORK24_JOB_INFO_KEY`로 되어 있어, 실제 키를 넣어도 라이브 API가 절대 켜지지 않는 이름 불일치 버그 발견. P5 확인 필요.
- `external_code`가 전부 빈 문자열이라 "직업정보 보러가기" 링크가 항상 work.go.kr 홈페이지로만 연결됨. 실제 직업 코드가 없어 임의로 채우지 않음(허위 링크 방지).

### 검증

- JSON 유효성 확인, 금지어(결핍어·단정어·예측어) 0건, `pytest -q` 6/6 통과.

- 사용자가 결과 화면(성향분석·직업추천) 콘텐츠가 전반적으로 부실하다고 지적. 점수는 이미 12축 전체가 계산되는데 화면엔 top3 문장 몇 줄만 노출되고 있었음 — 계산은 있는데 보여주는 게 얇았던 문제.
